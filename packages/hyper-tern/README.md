# Hyper-Tern

This package exists to hold the canonical **Hyper-Tern release version**.

It contains no code. The real backend and frontend live in [`../backend`](../backend) and [`../frontend`](../frontend), and shared types in [`../shared`](../shared). The Docker image at [`hypertern/hyper-tern`](https://hub.docker.com/r/hypertern/hyper-tern) bundles the built backend + frontend.

## What it's for

- **Changesets target**: `.changeset/config.json` ignores `hyper-tern-backend`, `hyper-tern-frontend`, and `hyper-tern-shared`, so when contributors run `npx changeset` the only selectable package is this one. Always target `hyper-tern` regardless of which files you actually changed — this is the single source of truth for "the version of Hyper-Tern as a whole".
- **Docker release version**: `.github/workflows/docker.yml` reads the `version` field from this package's `package.json` via `jq` and uses it to tag the image (`hypertern/hyper-tern:{version}` + derived `{major}.{minor}` / `{major}` / `sha-<short>` tags).
- **Changelog**: `CHANGELOG.md` here (auto-generated by changesets) is the unified Hyper-Tern release history.

## Adding a changeset

```bash
npx changeset
# → select "hyper-tern"
# → choose patch / minor / major
# → write a one-line summary
```

Commit the generated file. On merge to `main`, the release workflow opens a `chore: version packages` PR bumping `version` and appending to `CHANGELOG.md`. Merge that PR to land the version bump, then manually run the Docker workflow (`Actions → Docker → Run workflow` with a blank input) to publish.
